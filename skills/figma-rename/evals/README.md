## ต่างจาก `selftest.mjs` ยังไง

`selftest.mjs` ทดสอบว่า **สคริปต์** ทำงานถูก — 64 เคสบน boundary guard, การแทนที่
พร้อมกันตอนมี chain, การ refuse ของ check, calibration, staging กับ reverse
รันได้ในเครื่องเปล่า ไม่ต้องมี Figma

eval ทดสอบว่า **agent เดินกระบวนการถูก** — ถามเรื่อง convention ก่อนไหม
ดึงค่ามาด้วยหรือเอาแค่ชื่อ หยุดให้คนอ่าน `needsReview` ไหม regenerate ก่อน codemod ไหม
ผ่าน selftest ไม่ได้แปลว่าผ่าน eval คนละเรื่องกัน

## วิธีรัน

รันใน **เซสชันใหม่ที่ไม่เคยเห็นสกิลนี้** เพราะเซสชันที่ช่วยเขียนสกิลรู้เจตนาอยู่แล้ว
จึงมองไม่เห็นช่องว่าง

```
รอบ baseline   → เซสชันใหม่ ไม่โหลดสกิล  → ให้ query
รอบ with-skill → เซสชันใหม่ โหลดสกิล     → ให้ query เดิม
```

อย่างละ 3 ครั้ง เป้าหมายคือความคงเส้นคงวาของ*กระบวนการ* ครั้งเดียววัดไม่ได้

`eval-01` กับ `eval-02` ต้องมี Figma MCP ต่ออยู่และมีสิทธิ์เข้าไฟล์
ส่วน `eval-03` กับ `eval-04` จัดฉากได้ในเครื่อง ด้วยการเตรียม `rename-map.json`
และ `rename.config.json` ตามที่ระบุใน `files`

**`eval-04` แตะไฟล์ Figma จริง** ใช้ไฟล์ทดสอบเท่านั้น และเตรียมสคริปต์ `--reverse`
ไว้ก่อนเริ่ม

## วิธีให้คะแนน

แต่ละข้อใน `expected_behavior` ให้ผ่านหรือไม่ผ่าน ไม่มีคะแนนกลาง

ข้อที่ตกบอกว่าต้องไปแก้ที่ไหน: ตกเรื่องการยิง → แก้ `description` ใน `SKILL.md` ·
ตกเรื่องขั้นตอน → ลับถ้อยคำของขั้นนั้นใน `figma-rename.md` · ไม่เคยเปิดไฟล์แนบ
→ แก้ถ้อยคำ pointer ที่ชี้ไป `references/`

## กับดักพวกนี้มาจากไหน

ไม่ได้มาจากเซสชันที่ agent ทำพลาด แต่มาจากตอนสร้างและตอนทดสอบกับไฟล์จริง —
ระบุไว้ตรง ๆ เพราะมันเปลี่ยนวิธีอ่านผล:

- **variant trap** (eval-02) เจอตอนเขียนสคริปต์ inventory ถ้าไม่กรอง COMPONENT ที่เป็น
  ลูกของ COMPONENT_SET ออก convention จะแปลง `size=md, state=hover` เป็น
  `size-md/state-hover` แล้ว variant axis ของทั้งไฟล์พัง
- **values trap** (eval-02) วัดได้เป็นตัวเลข — inventory ที่ไม่มีค่า ทำให้ shade ถูกเดา
  จากตารางกลาง ซึ่งให้ผลถูก 23% กับ palette จริง เทียบกับ 91% ตอนเรียนจากไฟล์เอง
- **ramp ที่ hue ชนกัน** (eval-03) เจอตอนยิงกับ TestDSDS — `palette/red` กับ
  `palette/brand-primary` ห่างกัน 1° แต่ `500` อยู่คนละ lightness ทำให้ 48 จาก 256 ขั้น
  ตอบไม่ได้จริง ๆ
- **ลำดับ regenerate/codemod** (eval-04) เป็นเหตุผลที่ `check.mjs --after` ตั้งใจสแกน
  ไฟล์ generated ด้วย และมีเคสใน selftest คุมไว้

ถ้ารัน eval แล้วเจอช่องว่างใหม่ที่ไม่ได้อยู่ในนี้ ให้เพิ่มไฟล์ที่ห้า อย่าไปยัดรวมกับอันเดิม
— แต่ละอันควรทดสอบเส้นทางเดียว
