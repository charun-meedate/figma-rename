หกอันนี้ครอบเส้นทางหลัก — ตั้งต้น · อ่านของ · จุดตัดสินใจของคน · ลงจริงสองฝั่ง ·
มาตรฐานกลาง · **และโปรเจกต์ที่ไม่มี Figma เลย**

อันที่หกเพิ่มมาเพราะ "ลงจริงสองฝั่ง" กลายเป็นแค่*หนึ่ง*ในสองรูปแบบ ไม่ใช่รูปแบบเดียว
โปรเจกต์ที่ token เขียนมือไว้ในโค้ดใช้มาตรฐานเดียวกันและด่านรีวิวเดียวกัน แต่วงจรสั้นกว่า
และพลาดได้คนละแบบ — เส้นทางที่ไม่มี eval คือเส้นทางที่ regression มองไม่เห็น

## ต่างจาก `selftest.mjs` ยังไง

`selftest.mjs` ทดสอบว่า **สคริปต์** ทำงานถูก — 199 เคสบน boundary guard, การแทนที่
พร้อมกันตอนมี chain, การ refuse ของ check, calibration, staging กับ reverse
รันได้ในเครื่องเปล่า ไม่ต้องมี Figma

eval ทดสอบว่า **agent เดินกระบวนการถูก** — ถามเรื่อง convention ก่อนไหม
ดึงค่ามาด้วยหรือเอาแค่ชื่อ หยุดให้คนอ่าน `needsReview` ไหม regenerate ก่อน codemod ไหม
ผ่าน selftest ไม่ได้แปลว่าผ่าน eval คนละเรื่องกัน

## วิธีรัน

รันใน **เซสชันใหม่ที่ไม่เคยเห็นสกิลนี้** เพราะเซสชันที่ช่วยเขียนสกิลรู้เจตนาอยู่แล้ว
จึงมองไม่เห็นช่องว่าง

```
รอบ baseline   → เซสชันใหม่ ไม่โหลดสกิล  → ให้ query
รอบ with-skill → เซสชันใหม่ โหลดสกิล     → ให้ query เดิม
```

**รอบเดียวเป็นด่านผ่าน** ตกคือตก ไม่ต้องรันซ้ำเพื่อยืนยัน — รันซ้ำเมื่อผลจะเปลี่ยน
การตัดสินใจ คือตอนผ่านแบบก้ำกึ่ง หรือตอนที่ eval นั้นคุมส่วนที่เพิ่งแก้ ส่วน baseline
รันเมื่ออยากรู้ว่าสกิลเพิ่มอะไร ไม่ใช่ทุกครั้ง

ข้อจำกัดที่ต้องรับไว้: **รอบเดียววัดความคงเส้นคงวาไม่ได้** บอกได้แค่ว่ารอบนั้นผ่าน
ผลที่รันไปแล้วจริง ๆ อยู่ใน [`results.md`](results.md) — "มี eval 6 อัน" กับ
"eval 6 อันผ่าน" เป็นคนละเรื่องกัน

`eval-01` กับ `eval-02` ต้องมี Figma MCP ต่ออยู่และมีสิทธิ์เข้าไฟล์
ส่วน `eval-03` กับ `eval-04` จัดฉากได้ในเครื่อง ด้วยการเตรียม `rename-map.json`
และ `rename.config.json` ตามที่ระบุใน `files`

**`eval-04` แตะไฟล์ Figma จริง** ใช้ไฟล์ทดสอบเท่านั้น และเตรียมสคริปต์ `--reverse`
ไว้ก่อนเริ่ม

## วิธีให้คะแนน

แต่ละข้อใน `expected_behavior` ให้ผ่านหรือไม่ผ่าน ไม่มีคะแนนกลาง

ข้อที่ตกบอกว่าต้องไปแก้ที่ไหน: ตกเรื่องการยิง → แก้ `description` ใน `SKILL.md` ·
ตกเรื่องขั้นตอน → ลับถ้อยคำของขั้นนั้นใน `figma-rename.md` · ไม่เคยเปิดไฟล์แนบ
→ แก้ถ้อยคำ pointer ที่ชี้ไป `references/`

## กับดักพวกนี้มาจากไหน

ไม่ได้มาจากเซสชันที่ agent ทำพลาด แต่มาจากตอนสร้างและตอนทดสอบกับไฟล์จริง —
ระบุไว้ตรง ๆ เพราะมันเปลี่ยนวิธีอ่านผล:

- **variant trap** (eval-02) เจอตอนเขียนสคริปต์ inventory ถ้าไม่กรอง COMPONENT ที่เป็น
  ลูกของ COMPONENT_SET ออก convention จะแปลง `size=md, state=hover` เป็น
  `size-md/state-hover` แล้ว variant axis ของทั้งไฟล์พัง
- **values trap** (eval-02) วัดได้เป็นตัวเลข — inventory ที่ไม่มีค่า ทำให้ shade ถูกเดา
  จากตารางกลาง ซึ่งให้ผลถูก 23% กับ palette จริง เทียบกับ 91% ตอนเรียนจากไฟล์เอง
- **ramp ที่ hue ชนกัน** (eval-03) เจอตอนยิงกับ TestDSDS — `palette/red` กับ
  `palette/brand-primary` ห่างกัน 1° แต่ `500` อยู่คนละ lightness ทำให้ 48 จาก 256 ขั้น
  ตอบไม่ได้จริง ๆ
- **ลำดับ regenerate/codemod** (eval-04) เป็นเหตุผลที่ `check.mjs --after` ตั้งใจสแกน
  ไฟล์ generated ด้วย และมีเคสใน selftest คุมไว้
- **กับดัก dumps เก่า** (eval-04) มาจากการ audit รอบสอง — Step 5 เดิมไม่เคยบอกว่าต้อง
  re-capture dumps หลัง rename ใน Figma ทำให้ `sync.mjs` regenerate ชื่อเก่ากลับมาเงียบ ๆ
- **ไม่ถามเรื่อง format เลย** (จากการใช้งานจริงของเจ้าของ skill) — คำถาม 5 รอบอยู่ใน
  Step 0 ของคู่มือ แต่ `SKILL.md` ซึ่งเป็นไฟล์เดียวที่ถูกอ่านแน่ ๆ แสดงลูปที่เริ่มที่ `plan.mjs`
  ไม่มีคำว่า Step 0 เลย agent จึงเริ่มที่ plan ได้อย่างสมเหตุสมผล แล้วได้ชื่อ 20 ชื่อที่
  "ดูตัดสินใจแล้ว" ทั้งที่ไม่มีใครเลือก convention นั้น — eval-01 เขียนไว้ว่าต้องถาม แต่
  รันแล้วผ่านเพราะ agent ตัวนั้นบังเอิญอ่านคู่มือครบ
- **`source` ที่ลงมาแค่ครึ่ง** (eval-06) — ตัว config `source: "code"` ถูกเพิ่มพร้อมกับ
  `apply-code` ที่รู้จักมัน แต่ `mark`/`check`/`review` ยังอ่าน ladder ชุดเดียว ผลคือ
  `mark --applied` ไปไม่ถึงเลย และ `check --after` ตรวจ 0 ไฟล์แล้วขึ้นเขียว — ความผิดพลาด
  ที่มองไม่เห็นเพราะมัน *ผ่าน* กับดักนี้จึงไม่ใช่เรื่องที่ agent เดินผิด แต่เป็นเรื่องที่
  เครื่องมือโกหกได้อย่างสุภาพ
- **capture ที่พลาดไป 15% เงียบ ๆ** (eval-06) — snippet เดิมบังคับว่านิยาม CSS ต้องตามหลัง
  `{` หรือ `;` พอไฟล์จริงจัดเป็นหมวดพร้อมคอมเมนต์ นิยามที่ตามหลังคอมเมนต์หายไปทั้งหมด
  176 ตัวจับได้ 149 และไม่มีอะไรบอก — เป็นเหตุผลที่การ capture กลายเป็นสคริปต์ที่ทดสอบได้
  ไม่ใช่ snippet ในเอกสาร
- **plan ตายทั้งรอบเพราะ component ตัวเดียว** (eval-02 รอบสอง) — `result.to` เป็น null
  เมื่อชื่อมาจาก classifier ไม่ใช่จากกฎ ซึ่งเป็นเส้นทางปกติของ component พอเอาไปสร้าง
  code suggestion เลยพังทั้ง run: 1,222 entry, component ที่ชื่อดีอยู่แล้วตัวเดียว, ไม่ได้แผนเลย
  — บั๊กแบบนี้ selftest ไม่เจอเพราะ fixture ไม่มีเคส "ชื่อถูกอยู่แล้วแต่ classifier เห็นต่าง"
- **ทางลัด MCP** (eval-02) มาจากการรัน eval จริงครั้งแรก — agent ไม่ได้ใช้สคริปต์ capture
  ของ skill เลย ไปหยิบ `get_variable_defs` กับ `list_file_components_for_code_connect`
  ซึ่งพร้อมใช้กว่ามาก แล้วได้ inventory ที่ไม่มี id / ไม่มี scopes / ไม่มี collection /
  มีแต่ mode เริ่มต้น / และมีแค่ token ที่ถูกใช้จริง (368 จาก 1,148) รายงานออกมาดูดีมาก
  แต่เอาไปทำอะไรต่อไม่ได้เลย — นี่คือเหตุผลที่ Step 1 ตอนนี้ห้ามไว้ตรง ๆ พร้อมตาราง
  เทียบว่าเสียอะไรไปบ้าง
- **มาตรฐานแตกเป็นสองชุด** (eval-05) เป็นเหตุผลที่มี `extends` ตั้งแต่แรก และเป็นความผิดพลาด
  ที่มองไม่เห็นตอนเกิด — มันจะโผล่ตอนโปรเจกต์ที่สามถามว่าทำไมชื่อไม่ตรงกัน

ถ้ารัน eval แล้วเจอช่องว่างใหม่ที่ไม่ได้อยู่ในนี้ ให้เพิ่มไฟล์ใหม่ อย่าไปยัดรวมกับอันเดิม
— แต่ละอันควรทดสอบเส้นทางเดียว
