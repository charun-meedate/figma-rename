คุณไม่ต้องรันสคริปต์อะไรเอง **Claude Code เป็นคนทำให้** คุณมีหน้าที่สองอย่างเท่านั้น:
**ตกลงว่าชื่อควรเป็นแบบไหน** กับ **อ่านข้อเสนอก่อนกดอนุมัติ** คู่มือนี้บอกว่าต้องพูดอะไร
และจะได้อะไรกลับมา

## เข้าใจข้อเดียวก่อนเริ่ม

```
Figma ผูกด้วย id    →  เปลี่ยนชื่อแล้วไม่มีอะไรพัง
โค้ดผูกด้วยชื่อ     →  เปลี่ยนชื่อแล้วพังทุกที่ที่อ้างถึง
```

การ rename จึงไม่ใช่งานใน Figma อย่างเดียว แต่คือ**การเปลี่ยนแปลงหนึ่งก้อนที่ต้องลง
พร้อมกันทั้งสองฝั่ง** skill นี้เลยบังคับให้ทำทีละก้อน ก้อนละ commit — ไม่ใช่ความเรียบร้อย
แต่เป็นสิ่งเดียวที่ทำให้ย้อนกลับได้ตอนพลาด

---

## เตรียมครั้งเดียว

1. เปิดลิงก์ไฟล์ Figma ที่จะแก้ได้ (มีสิทธิ์ **แก้ไข** ไม่ใช่แค่ดู)
2. ติดตั้ง skill ลงโปรเจกต์:

```bash
git clone <url-ของ-repo-นี้> ~/dev/figma-rename
~/dev/figma-rename/install.sh ~/dev/my-project
```

3. **โปรเจกต์ต้องอยู่ใน git และไม่มีของค้าง** — skill จะ commit ให้ทีละ batch
   ถ้ามีงานค้างอยู่ diff จะปนกันจนอ่านไม่ออก

## ครั้งแรก — บอก Claude ว่าจะแก้อะไร

เปิด Claude Code ในโปรเจกต์ แล้วพิมพ์ประมาณนี้ **พร้อมแปะลิงก์ Figma**:

> เปลี่ยนชื่อ token ในไฟล์นี้ให้ตรง convention หน่อย เริ่มจาก collection Primitive ก่อน
> https://www.figma.com/design/SjE7hLqGcKYLy4XMgXGhlM/Design-system

บอกด้วยว่าจะแก้อะไรบ้าง — เลือกได้หลายอย่าง แต่ **อย่าเอาทีเดียวหมด**:

| แก้อะไร | เหมาะกับ |
|---|---|
| **Variables (token)** | งานส่วนใหญ่ กระทบโค้ดมากที่สุด |
| **Component / Component Set** | ชื่อ component เอง |
| **Layer ข้างใน component** | ทีละ component เท่านั้น ไม่ใช่ทั้งไฟล์ |
| **Text / Effect styles** | typography, shadow |

## Claude จะถามเป็นรอบ ๆ — ตอบตามที่รู้ ไม่รู้ก็บอกว่าไม่รู้

ทุกคำถามมี**ข้อเสนอของ Claude มาให้ก่อน** ตอบว่า "เอาตามนั้น" ได้เสมอ
ไม่ต้องรู้ศัพท์ก่อนถึงจะเริ่มได้

**รอบ 0 — ชื่อพวกนี้อยู่ที่ไหน** — เก็บใน Figma แล้วโค้ดตามมา · เขียนมือไว้ใน repo ไม่มีอะไร
อยู่ข้างหลัง · หรือมีทั้งสองอย่างแล้วเริ่มไม่ตรงกัน ถามก่อนขอลิงก์ Figma ด้วยซ้ำ เพราะคำตอบ
หนึ่งแปลว่าไม่มีลิงก์ให้ขอ และถ้าตอบว่ามีทั้งคู่ ต้องตัดสินก่อนว่าฝั่งไหนเป็นต้นทาง

**รอบ 1 — มาตรฐานมาจากไหน** (ก่อนแตะอะไรทั้งสิ้น)

นี่คือคำถามที่สำคัญที่สุด และเป็นคำถามที่คนมักข้าม ตอบได้ 3 แบบ:

| ทีมมีอะไรอยู่ | สิ่งที่ควรตอบ | ได้อะไร |
|---|---|---|
| มีเอกสาร convention อยู่แล้ว | ส่งไฟล์ MD / ลิงก์ Confluence มา | Claude แปลงเป็น**ไฟล์กลาง** แล้วให้โปรเจกต์นี้ `extends` |
| ยังไม่มี แต่รู้ว่าอยากได้อะไร | ยกตัวอย่างจริง 5–10 คู่ | Claude ย้อนกลับเป็นกฎ แล้วเก็บเป็นไฟล์กลางให้ |
| ไม่รู้เลย | บอกตรง ๆ | ได้ `"extends": "starter"` เป็นจุดตั้งต้น ปรับทีหลังได้ |

**อย่าปล่อยให้กฎไปอยู่ใน `rename.config.json` ของโปรเจกต์** พอโปรเจกต์ที่สองทำแบบเดียวกัน
มาตรฐานจะแตกเป็นสองชุดที่ "เหมือนกันตอนนี้" แล้วค่อย ๆ ห่างกันโดยไม่มีใครสังเกต
ของโปรเจกต์ควรมีแค่ข้อเท็จจริงของโปรเจกต์เอง — fileKey, prefix ของโค้ด, path ไฟล์ generated

```jsonc
{ "extends": "../design-system/naming.json",   // มาตรฐานอยู่ที่นี่
  "figma": { "fileKey": "…" },                  // ที่เหลือคือของโปรเจกต์นี้เท่านั้น
  "code":  { "cssPrefix": "", "flutterPrefix": "App" } }
```

**รอบ 2 — จะแก้อะไร** — token / component / layer / style และ collection ไหนก่อน
ควรเริ่มจากอันที่เล็กที่สุดเสมอ

**รอบ 3 — รูปแบบชื่อ** (ถามหลังดึงของออกมาแล้วเท่านั้น) — ตัวพิมพ์ · prefix ที่จะตัดทิ้ง ·
ตัวคั่น · เลขขนาดจะเป็น `sm/md/lg` หรือ `100/200/300` ทุกข้อจะยกชื่อจริงจากไฟล์คุณ
มาเทียบให้ดู ไม่ใช่ตัวอย่างลอย ๆ

**รอบ 4 — ตัวที่เครื่องตัดสินไม่ได้** — ดูหัวข้อถัดไป

**รอบ 5 — ยืนยันก่อนลงจริง** — batch นี้กี่ตัว กระทบโค้ดกี่ไฟล์ ย้อนยังไง

> ถ้าจะแก้ชื่อ **component** ด้วย Claude จะอ่านโครงสร้างข้างในแต่ละตัว (มีปุ่มไหม
> มี input ไหม ซ้อนกันกี่ชั้น) แล้วเดาว่ามันคืออะไร — `Frame 427` ที่มีข้อความกับ
> พื้นหลังโค้งมนจะถูกเสนอเป็น `Button` พร้อมเหตุผล ปรับความเข้มงวดได้ที่
> `components.classifier` ใน preset

## Claude จะหยุดให้ดู 2 จุด — อย่ากดผ่านรวด

### จุดที่ 1 — ข้อเสนอชื่อใหม่

```
[plan] 742 inventory entries in scope
[plan]   renamed     354      ← กฎที่ตกลงกันไว้ match
[plan]   suggested    88      ← ค่าของตัวมันเองบอกได้ว่าคืออะไร
[plan]   conforming  361      ← ถูกอยู่แล้ว ไม่แตะ
[plan]   needsReview   9      ← ตัดสินให้ไม่ได้ ต้องคุณตอบ
```

**`needsReview` คือส่วนที่ต้องอ่านจริง ๆ** มันคือสิ่งที่ไม่มีสูตรไหนตอบได้ เช่น

```
Color 5 — alias ของ colors/blue/500 — เป็น semantic token ชื่อคือ "role" ของมัน
          (brand? error? surface?) ซึ่งค่าบอกไม่ได้
Color 1 — ค่าเดียวกับ "primary" — ทั้งคู่จะได้ชื่อ colors/blue/500
          ควรรวมกัน หรือทำตัวหนึ่งเป็น alias ของอีกตัว
```

ตอบพวกนี้ให้ครบก่อนไปต่อ ที่เหลือดูผ่าน ๆ ได้

**Claude จะไม่ไล่ถามทีละแถว** ต่อให้มี 300 ตัวก็ตาม มันจะจัดกลุ่มตามกฎที่ทำให้เกิด
แล้วถามเป็นกลุ่ม:

```
กฎ "ตัด prefix color/" เข้าเงื่อนไข 214 ตัว — เอาทั้งกลุ่มไหม
   color/text-primary → text/primary     color/bg-raised → surface/raised   … อีก 212
```

ตอบได้ว่าเอาทั้งกลุ่ม · ไม่เอาทั้งกลุ่ม · หรือเอาเฉพาะบางตัว ทุกคำตอบถูกบันทึกลง
`rename-map.json` ทันที ไม่ได้ค้างอยู่ในบทสนทนา — ปิดเครื่องแล้วพรุ่งนี้มาต่อได้
และการวางแผนใหม่จะไม่ลบสิ่งที่คุณตัดสินไปแล้ว

ตัวที่ยังไม่ได้ตัดสิน **ยิงขึ้น Figma ไม่ได้** สคริปต์จะปฏิเสธเอง ไม่ใช่แค่เตือน

### จุดที่ 2 — ตัวเลขที่บอกว่าเชื่อได้แค่ไหน

ชื่อที่มาจากค่าจะมี **เหตุผล** กับ **ความมั่นใจ** ติดมาเสมอ:

```
Value 1      -> spacing/md       [high]   collection "Spacing"; scope GAP; 16 หาร 4 ลงตัว
heading      -> fontSize/2xl     [medium] scope FONT_SIZE; 24 อยู่ในช่วง type scale
Variable 3   -> opacity/50       [low]    0.5 อยู่ในช่วง 0–1
```

ดู `[low]` ก่อน — พวกนั้นคือการเดาที่มีสัญญาณเดียว บอก Claude ให้ตัดออกได้
(`--min-confidence medium`) หรือแก้ชื่อเองทีละตัว

## เสร็จแล้วเกิดอะไรขึ้น

Claude จะทำทีละ batch วนแบบนี้จนครบ:

```
1. แก้ชื่อใน Figma (batch นี้)
2. บันทึกว่า Figma ลงแล้ว        ← ถ้าข้าม ขั้น 4 จะไม่ยอมทำงาน
3. ดึงของจาก Figma ใหม่ แล้ว regenerate ไฟล์ token
4. แก้โค้ดทุกที่ที่เรียกใช้ชื่อเก่า
5. build / test
6. บันทึกว่า batch นี้จบ แล้ว commit
```

**ขั้น 3 ต้องดึงของใหม่ก่อน** ไม่งั้น regenerate จากของเก่าที่ยังเป็นชื่อเดิม
แล้วชื่อเก่าจะกลับมาแบบเงียบ ๆ ทั้งที่ทุกอย่างดูเขียว

ระหว่างขั้น 1–4 โค้ดจะ compile ไม่ผ่าน — ปกติ ห้ามแค่อย่า commit ตอนนั้น
(Claude จัดการให้อยู่แล้ว)

สรุปที่จะได้:

```
[apply-code] rewrote 1,204 occurrence(s) in 87 file(s)
[check] OK — ไม่เหลือชื่อเก่าที่ไหนเลย
```

## ถ้าพลาด

บอก Claude ว่า **"ย้อน batch นี้"** มันจะทำสองอย่าง: ยิงสคริปต์ย้อนชื่อกลับใน Figma
แล้ว `git revert` commit นั้น — ทำได้เพราะ 1 batch = 1 commit เท่านั้น

---

## 4 ข้อห้าม

1. **อย่าให้แก้ทีเดียวทั้งไฟล์** — 400 ชื่อรวดเดียวไม่มีใคร review ไหว และย้อนไม่ได้
   เริ่มจาก collection ที่มี 10–20 ตัวก่อนเสมอ โดยเฉพาะครั้งแรก
2. **อย่า rename กับแก้ค่าใน batch เดียวกัน** — พอมีอะไรผิด จะแยกไม่ออกว่าเพราะครึ่งไหน
3. **อย่ารีบผ่าน `needsReview`** — มันคือส่วนที่เครื่องยอมแพ้แล้วส่งมาให้คน
   ถ้าข้ามไป สิ่งที่ได้คือชื่อที่ดูดีแต่ผิดความหมาย ซึ่งแย่กว่าไม่แก้เลย
4. **อย่าแก้ `rename-map.json` ด้วยมือ** — มันเป็นบันทึกสถานะ ไม่ใช่ไฟล์ตั้งค่า
   บอก Claude ว่าอยากเปลี่ยนชื่อไหนเป็นอะไร แล้วให้มันบันทึกให้ การแก้เองจะหายตอนวางแผนใหม่

## ถ้า Claude บอกว่าติดอะไร แปลว่า...

| ข้อความ | แปลว่า | ทำยังไง |
|---|---|---|
| `re-capture the inventory` | มีคนแก้ชื่อใน Figma ระหว่างที่เรากำลังวางแผน | ให้ดึงใหม่แล้ววางแผนใหม่ ปลอดภัยกว่าฝืน |
| `Identifier collision` | สองชื่อที่ต่างกันใน Figma กลายเป็นชื่อเดียวในโค้ด | ต้องเปลี่ยนชื่อใหม่ให้ตัวใดตัวหนึ่ง |
| `library (remote) entity` | ตัวนั้นมาจากไฟล์อื่น แก้จากไฟล์นี้ไม่ได้ | ไปแก้ที่ไฟล์ต้นทาง |
| `built-in ladder (no ramp to learn from)` | เดา shade สีจากตารางกลาง ไม่ได้เรียนจาก palette คุณ | เช็คว่า inventory ดึง**ค่า**มาด้วยไหม ถ้าไม่ ชื่อ shade อาจเพี้ยน |
| `namespace splits into…` | หมวดเดิมแตกเป็นหลายหมวดใหม่ ไม่มีชื่อ class ใหม่ตัวเดียวที่ถูก | ปล่อยให้ compiler ชี้จุดที่ต้องแก้เอง |
| `has pending decisions` | มีตัวที่ยังไม่ได้ตอบว่าเอาหรือไม่เอา | ตอบให้ครบก่อน — สคริปต์ไม่ยอมยิงของที่ยังไม่ตัดสิน |
| `planned under a different convention` | กฎถูกแก้หลังวางแผนไว้แล้ว แผนเก่าจึงไม่ตรงกฎใหม่ | ให้วางแผนใหม่ สิ่งที่ตัดสินไปแล้วไม่หาย |
| `another batch is in flight` | batch ก่อนหน้ายังค้างกลางทาง | ทำอันเก่าให้จบก่อน — สองก้อนพร้อมกันแปลว่าย้อนไม่ได้ทั้งคู่ |
| `not in a git repository` | ย้อนกลับด้วย `git revert` ไม่ได้ เพราะโปรเจกต์ไม่ได้อยู่ใน git | `git init` ก่อนถ้าทำได้ ถ้าไม่ได้ ต้องเก็บ `rename/rename-map.json` ไว้ให้ดี — หายเมื่อไหร่คือย้อนไม่ได้ |
| `Ambiguous rewrite` | ชื่อ class ที่ generator สร้างชนกัน (เจอบ่อยตอน rename `colors/**`) | ถ้าโปรเจกต์ไม่มีโค้ด Dart ให้เติม `--no-namespace-classes` ข้อความ error บอกไว้แล้ว |
| `cssPrefix mismatch` | prefix ที่ตั้งไว้ที่นี่ไม่ตรงกับ `tokens.config.json` | แก้ให้ตรงกัน ไม่งั้นโค้ดที่ generate ออกมาจะคนละชื่อกับที่ codemod แก้ |
