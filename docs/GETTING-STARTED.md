# วิธีใช้ — สำหรับคนที่จะเปลี่ยนชื่อ token / component ทั้งชุด

> ภาษาไทย · [English](GETTING-STARTED.en.md)
> ดูแลตัว skill เอง / อยากรู้ว่าข้างในทำงานยังไง → [MAINTAINING.md](MAINTAINING.md) · [REFERENCE.md](REFERENCE.md)

คุณไม่ต้องรันสคริปต์อะไรเอง **Claude Code เป็นคนทำให้** คุณมีหน้าที่สองอย่างเท่านั้น:
**ตกลงว่าชื่อควรเป็นแบบไหน** กับ **อ่านข้อเสนอก่อนกดอนุมัติ** คู่มือนี้บอกว่าต้องพูดอะไร
และจะได้อะไรกลับมา

---

## เข้าใจข้อเดียวก่อนเริ่ม

```
Figma ผูกด้วย id    →  เปลี่ยนชื่อแล้วไม่มีอะไรพัง
โค้ดผูกด้วยชื่อ     →  เปลี่ยนชื่อแล้วพังทุกที่ที่อ้างถึง
```

การ rename จึงไม่ใช่งานใน Figma อย่างเดียว แต่คือ**การเปลี่ยนแปลงหนึ่งก้อนที่ต้องลง
พร้อมกันทั้งสองฝั่ง** skill นี้เลยบังคับให้ทำทีละก้อน ก้อนละ commit — ไม่ใช่ความเรียบร้อย
แต่เป็นสิ่งเดียวที่ทำให้ย้อนกลับได้ตอนพลาด

---

## เตรียมครั้งเดียว

1. เปิดลิงก์ไฟล์ Figma ที่จะแก้ได้ (มีสิทธิ์ **แก้ไข** ไม่ใช่แค่ดู)
2. ติดตั้ง skill ลงโปรเจกต์:

```bash
git clone <url-ของ-repo-นี้> ~/dev/design-tokens-skill
~/dev/design-tokens-skill/install.sh ~/dev/my-project --skill figma-rename
```

3. **โปรเจกต์ต้องอยู่ใน git และไม่มีของค้าง** — skill จะ commit ให้ทีละ batch
   ถ้ามีงานค้างอยู่ diff จะปนกันจนอ่านไม่ออก

---

## ครั้งแรก — บอก Claude ว่าจะแก้อะไร

เปิด Claude Code ในโปรเจกต์ แล้วพิมพ์ประมาณนี้ **พร้อมแปะลิงก์ Figma**:

> เปลี่ยนชื่อ token ในไฟล์นี้ให้ตรง convention หน่อย เริ่มจาก collection Primitive ก่อน
> https://www.figma.com/design/SjE7hLqGcKYLy4XMgXGhlM/Design-system

บอกด้วยว่าจะแก้อะไรบ้าง — เลือกได้หลายอย่าง แต่ **อย่าเอาทีเดียวหมด**:

| แก้อะไร | เหมาะกับ |
|---|---|
| **Variables (token)** | งานส่วนใหญ่ กระทบโค้ดมากที่สุด |
| **Component / Component Set** | ชื่อ component เอง |
| **Layer ข้างใน component** | ทีละ component เท่านั้น ไม่ใช่ทั้งไฟล์ |
| **Text / Effect styles** | typography, shadow |

## Claude จะถามกลับ 1 เรื่อง — เรื่อง convention

**"ชื่อควรเป็นแบบไหน"** ต้องตอบให้ชัดตั้งแต่แรก เพราะมันคือสิ่งที่ทำให้ผลลัพธ์ review ได้
คำถามตอนตรวจจะกลายเป็น *"ตรงกฎไหม"* แทน *"ชอบชื่อนี้ไหม"*

ตอบได้ 3 แบบ แล้วแต่ว่าทีมมีอะไรอยู่:

**ก. มีเอกสาร convention อยู่แล้ว** — ส่งไฟล์ MD / ลิงก์ Confluence ให้ Claude อ่าน
มันจะแปลงเป็นกฎให้เอง ดีที่สุด

**ข. ยังไม่มี แต่รู้ว่าอยากได้อะไร** — ยกตัวอย่างจริงมา 5–10 คู่ก็พอ:

> `color/text-primary` → `text/primary/default`
> `color/bg-raised` → `surface/raised`

Claude จะย้อนกลับเป็นกฎให้ แล้วเอาไปใช้กับที่เหลือทั้งหมด

**ค. ไม่รู้เลย ให้ช่วยคิด** — บอกไปตรง ๆ ได้ Claude จะเสนอโครงให้ดูก่อน
(อ่าน `naming-convention.md` ในตัว skill ประกอบ)

---

## Claude จะหยุดให้ดู 2 จุด — อย่ากดผ่านรวด

### จุดที่ 1 — ข้อเสนอชื่อใหม่

```
[plan] 742 inventory entries in scope
[plan]   renamed     354      ← กฎที่ตกลงกันไว้ match
[plan]   suggested    88      ← ค่าของตัวมันเองบอกได้ว่าคืออะไร
[plan]   conforming  361      ← ถูกอยู่แล้ว ไม่แตะ
[plan]   needsReview   9      ← ตัดสินให้ไม่ได้ ต้องคุณตอบ
```

**`needsReview` คือส่วนที่ต้องอ่านจริง ๆ** มันคือสิ่งที่ไม่มีสูตรไหนตอบได้ เช่น

```
Color 5 — alias ของ colors/blue/500 — เป็น semantic token ชื่อคือ "role" ของมัน
          (brand? error? surface?) ซึ่งค่าบอกไม่ได้
Color 1 — ค่าเดียวกับ "primary" — ทั้งคู่จะได้ชื่อ colors/blue/500
          ควรรวมกัน หรือทำตัวหนึ่งเป็น alias ของอีกตัว
```

ตอบพวกนี้ให้ครบก่อนไปต่อ ที่เหลือดูผ่าน ๆ ได้

### จุดที่ 2 — ตัวเลขที่บอกว่าเชื่อได้แค่ไหน

ชื่อที่มาจากค่าจะมี **เหตุผล** กับ **ความมั่นใจ** ติดมาเสมอ:

```
Value 1      -> spacing/md       [high]   collection "Spacing"; scope GAP; 16 หาร 4 ลงตัว
heading      -> fontSize/2xl     [medium] scope FONT_SIZE; 24 อยู่ในช่วง type scale
Variable 3   -> opacity/50       [low]    0.5 อยู่ในช่วง 0–1
```

ดู `[low]` ก่อน — พวกนั้นคือการเดาที่มีสัญญาณเดียว บอก Claude ให้ตัดออกได้
(`--min-confidence medium`) หรือแก้ชื่อเองทีละตัว

## เสร็จแล้วเกิดอะไรขึ้น

Claude จะทำทีละ batch วนแบบนี้จนครบ:

```
1. แก้ชื่อใน Figma (batch นี้)
2. regenerate ไฟล์ token
3. แก้โค้ดทุกที่ที่เรียกใช้ชื่อเก่า
4. build / test
5. commit
```

ระหว่างขั้น 1–3 โค้ดจะ compile ไม่ผ่าน — ปกติ ห้ามแค่อย่า commit ตอนนั้น
(Claude จัดการให้อยู่แล้ว)

สรุปที่จะได้:

```
[apply-code] rewrote 1,204 occurrence(s) in 87 file(s)
[check] OK — ไม่เหลือชื่อเก่าที่ไหนเลย
```

---

## ถ้าพลาด

บอก Claude ว่า **"ย้อน batch นี้"** มันจะทำสองอย่าง: ยิงสคริปต์ย้อนชื่อกลับใน Figma
แล้ว `git revert` commit นั้น — ทำได้เพราะ 1 batch = 1 commit เท่านั้น

---

## 3 ข้อห้าม

1. **อย่าให้แก้ทีเดียวทั้งไฟล์** — 400 ชื่อรวดเดียวไม่มีใคร review ไหว และย้อนไม่ได้
   เริ่มจาก collection ที่มี 10–20 ตัวก่อนเสมอ โดยเฉพาะครั้งแรก
2. **อย่า rename กับแก้ค่าใน batch เดียวกัน** — พอมีอะไรผิด จะแยกไม่ออกว่าเพราะครึ่งไหน
3. **อย่ารีบผ่าน `needsReview`** — มันคือส่วนที่เครื่องยอมแพ้แล้วส่งมาให้คน
   ถ้าข้ามไป สิ่งที่ได้คือชื่อที่ดูดีแต่ผิดความหมาย ซึ่งแย่กว่าไม่แก้เลย

## ถ้า Claude บอกว่าติดอะไร แปลว่า...

| ข้อความ | แปลว่า | ทำยังไง |
|---|---|---|
| `re-capture the inventory` | มีคนแก้ชื่อใน Figma ระหว่างที่เรากำลังวางแผน | ให้ดึงใหม่แล้ววางแผนใหม่ ปลอดภัยกว่าฝืน |
| `Identifier collision` | สองชื่อที่ต่างกันใน Figma กลายเป็นชื่อเดียวในโค้ด | ต้องเปลี่ยนชื่อใหม่ให้ตัวใดตัวหนึ่ง |
| `library (remote) entity` | ตัวนั้นมาจากไฟล์อื่น แก้จากไฟล์นี้ไม่ได้ | ไปแก้ที่ไฟล์ต้นทาง |
| `built-in ladder (no ramp to learn from)` | เดา shade สีจากตารางกลาง ไม่ได้เรียนจาก palette คุณ | เช็คว่า inventory ดึง**ค่า**มาด้วยไหม ถ้าไม่ ชื่อ shade อาจเพี้ยน |
| `namespace splits into…` | หมวดเดิมแตกเป็นหลายหมวดใหม่ ไม่มีชื่อ class ใหม่ตัวเดียวที่ถูก | ปล่อยให้ compiler ชี้จุดที่ต้องแก้เอง |
